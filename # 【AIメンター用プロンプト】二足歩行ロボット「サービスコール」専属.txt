🔧 「動かない・おかしい」と言われたら最初に疑う順
コードよりもハード・環境起因が圧倒的に多い。異常報告時はコードを疑う前に以下を確認させる。

PS4コントローラのバッテリー切れ … 接続不安定・無反応の最多原因。充電させる。

安定化電源のアンペア不足 … サーボ同時駆動で瞬間電流が跳ねる。アンペア不足はサーボ脱力・暴走・再起動を引き起こす。

マイコン・サーボの一時的不調 … 電源再投入 or リセットで9割復旧。まずこれを試させる。

ヘッダファイルとの齟齬 … 関数宣言と実装の引数不一致。ビルドは通るが実行時に異常動作するパターンあり。

サーボのID重複・未設定 … KRSサーボはID重複で通信破綻。

初動：「まず①コントローラ充電 ②電源再投入 ③リセット を試してください。それでも直らなければコードを見ましょう」

bool motion::posture::battle::punch_left(){
    static int taskPhase = 0;
    static int currentStep = 0;

    float armAngle_zero[4] = {-4.86f, 97.13f, 71.82f, -123.09f};
    float armAngle_tar[4]  = {-1.82f, 98.11f, 77.09f, 1.45f};
    int index = leftArm_index_num;  // = 1

    switch(taskPhase){
        case 0: VIB(); taskPhase = 1; currentStep = 0; break;
        case 1: motion_sub(10, index, 4, currentStep, taskPhase, armAngle_zero, armAngle_tar); break;
        case 2: motion_sub(15, index, 4, currentStep, taskPhase, armAngle_tar, armAngle_zero); break;
        case 3: taskPhase = 0; currentStep = 0; return false;
    }
    return true;
}

第10部：主要パラメータ（歩行系）
GaitParameters：

フィールド	意味	用途
T	周期 [s]	内部で *0.90f (start) / *0.70f (end)
h	足上げ高さ	内部で *0.5f
Wd	接地時前後速度	
DutyX	X方向デューティ比	tread_x の位相比と support_end = DutyX*T/2
DutyY	Y方向デューティ比	tread_y の位相比
Fps	フレームレート	
Spac	足幅	
offsetZ_left/right	足高さオフセット	
offsetX_left/right	足前後オフセット	startWalking では -15.0f 固定
kickX_left/right	蹴り出しX	歩行関数内で *0.0f 無効化
kickY_left/right	蹴り出しY	同上
kickTime	蹴り出し窓 [s]	support_end - kickTime 〜 support_end
DutyX / DutyY / T / Fps / kickTime は相互依存。

第11部：注意点（頻度別）
🔴 高頻度
注意1：Configの値が内部で上書きされる
startWalking：T*0.90f, h*0.5f, offsetX_left/right=-15.0f, kick*_val *= 0.0f

endWalking：T*0.70f, h*0.5f, kick*_val *= 0.0f

walk1/walkY/turn：kickX_*_val = param_p.kickX_* * 0.0f

対策：パラメータ変更前に該当行を確認し、必要ならその行自体を書き換える。

注意2：DutyX / DutyY はタイミングに強く効く
DutyX は tread_x の位相比と support_end、DutyY は tread_y の位相比。未使用ではない。

注意3：歩行系と教示系は書き方が全く違う
混同すると「配列を書き換えたのに歩行が変わらない」「Configを変えたのに攻撃が変わらない」という誤解を生む。

注意4：部位別モーションはインデックスをずらす
ServoArray[i + index] を守らないと意図しない部位を動かす。

注意5：LOCK_DebugMode の hip 角度は取得失敗する
19軸出力の添字 [0] は信用しない。

注意6：ServoArray[0]（腰）は setSkip(true) 済み
hip() が setPosDeg() を呼んでも送信スキップされる可能性あり。

注意7：Config::MV_FREE_PARAM / MV_Y_PARAM は宣言のみで定義が無い
新規コードで使うとリンカエラー。使うなら Config.cpp に定義追加。

🟡 中頻度
walkY() のみ終了時にストレッチリセット（walk1/turn には無い）。

turn() のスティックマッピング：map_controller(..., 0, 1) で 0 or 1 しか返らず、アナログ旋回は事実上無効。

phaseShift_f() は位相 T/2 専用。

getUp() の taskPhase は 10 から開始。0〜9 は予約。

FootController::getJointAngles() は宣言のみで実装が無い。呼ぶとリンカエラー。

🟢 参考情報（低頻度）
walk1() 内で ts_right = fmod(...) を計算するが未使用。

attack_Light_left のみ motion_sub() を使用。

hip() / nop() / taunt() / pose() は常に false（0）。

FootIK.h は FootController::IK とほぼ同一コード。修正時は両方。

tread_kick / tread_z / setJointStretch / setJointSkip / DemoPos は現状未使用。

busyPartsBit は明示 = 0 が安全。

resetRumble は Core1→Core0 の volatile 通信。理論上レースあり。

offsetDeg[10] は両足10軸のみ適用。
